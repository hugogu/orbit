# ORBIT solar observatory

- Preserve the Sites project identifier and scaffold. Three.js scene is in `components/solar-scene.tsx`; educational parameters and Kepler solver are in `lib/solar.ts`.
- The simulation clock is UTC (1700–2200). Astronomy Engine drives Sun/planet/Pluto/Moon positions and orientation plus Galilean satellite positions. Other satellites use fixed JPL mean elements; comets use epoch-aware two-body snapshots. Never describe those approximate trajectories as precision ephemerides. Display sizes and distances are independently configurable; both real switches share a physical scale through `lib/display-scale.ts`. Outer particles and comet nuclei remain schematic; sky events are calculated separately from rendering.
- Run `npm test`, `npm run lint`, `npx tsc --noEmit`, and `npm run build` before publishing changes.
- In macOS sandboxed sessions, networking and preview listeners may require approved elevated execution. Use `node --import tsx --test` instead of the tsx CLI to avoid its unnecessary IPC socket.
- Lint excludes unmodified vendored `components/ui` and the scaffold's mobile hook; application files remain fully checked.
- Reuse the current development server and browser tab. Verify responsive behavior using browser viewport controls, then reset the override.
- All planet textures are local assets from Solar System Scope (CC BY 4.0). Preserve attribution in the model explanation and README.

- With Y as north, map ecliptic in-plane sine to negative Z so prograde orbits and positive axial spins agree. The orbit orientation test protects this convention.
- The followed body's live speed and ecliptic longitude come from `lib/body-motion.ts`, which central-differences the very path the scene draws rather than keeping a second set of elements: planets and comets and asteroids report their motion around the Sun, moons theirs around their own planet, and the Sun reports nothing. Astronomy Engine's `Ecliptic()` answers in the true ecliptic of date, which precession pulls degrees away from the fixed J2000 frame this scene renders in — use `Rotation_EQJ_ECL` for anything that must line up with the rendered geometry. Its published Galilean velocities are not the derivative of its published positions either, trailing them by about 0.03%. A moon's mean-element period in `lib/satellite-elements.ts` is not its catalog period in `lib/moon-orbits.ts`, so read a model's speed back as a gravitational parameter instead of assuming the two agree.
- The status line above playback carries three readouts and the side rails claim most of its width, so it wraps and the followed body's name is what ellipsizes: the numbers stay whole and the panel already spells the name out. Check the longest name in each language, which is a comet, against the info panel edge near 900px.
- Wide screen-space orbit paths use dense sampling (at least 2,048 segments per closed path) and render after the opaque bodies, depth-tested but with an opaque material and depth writes disabled. Opaque colour plus no depth writes keeps adjacent wide-line segments from blending or occluding each other, while the body depth already in the buffer hides far-side arcs only — drawing the guides beneath the bodies instead would bury a moon's whole ring inside its planet's disc.
- This source host may reject chunked Git uploads with HTTP 400; per-command `http.postBuffer=157286400` and `http.version=HTTP/1.1` succeeded. Do not persist source tokens in Git configuration.
- Vinext static export can turn `new Worker(new URL(..., import.meta.url))` into an inaccessible file URL. Import the worker with Vite's `?worker` constructor, and verify an actual calculation in the exported browser build. Handle constructor failures as well as worker error events.
- Eclipse shadows must use physical vectors/radii from `lib/eclipse-shadows.ts`, never the enlarged scene geometry. Surface uniforms are receiver-radius units in the mesh's rotating frame. Compare the 2024 eclipse axis with Mexico, and protect total/annular classification and scale independence. Guide lines must not intercept celestial picking. Native datetime fields in the in-app browser may reject automated fill; click day/month/year steppers individually (typing can auto-advance) and verify the resulting value.
- Full eclipse paths use Earth-fixed unit-sphere coordinates and background calculation. Keep global contacts distinct from local visibility, include both sides of midnight, and hide stale results after seeks. Swept footprints must blend only once per pixel; preserve the renderer's stencil buffer. Check the collapsed progress card against the globe and the expanded card against playback controls on short portrait and landscape screens.
- The one simulation clock belongs to playback and the observation point belongs to Earth: seeking lives beside the timeline's play and "now" controls, coordinates live beside the sunrise/sunset card that consumes them, and the sky panel only lists what it computed. A control that reads `now-button` styling must not also carry that class, or the timeline's per-breakpoint `grid-column` rules place both buttons in the same cell.
- `SearchGlobalSolarEclipse` and `SearchLocalSolarEclipse` are different series over the same eclipses: the local one skips eclipses that never reach the observer, and its `peak` is that site's own maximum, tens of minutes off the global peak the catalogs list. Walk them as two ordered cursors and match within half a day; never present a local peak as the global one. `localSolarVisible` also admits an eclipse whose maximum is below the horizon when the Sun rises during it, so read the altitude alongside that rule rather than assuming a visible eclipse is an eclipse in the sky. A site can wait decades for one, so look it up separately and pair it with its own global entry instead of walking the global series there one new moon at a time. A penumbral lunar eclipse reports zero obscuration because it reaches no umbra; do not print that zero.
- Paging the eclipse list continues the global run alone: the visible eclipse appended past it is a preview, and resuming from that one would skip every eclipse in between. A page's cursor is one tick past its last event, because a page includes an eclipse falling exactly on its start. Each search begins at a new moon and can land back on the eclipse the cursor just passed, so a candidate before the start is stepped over rather than read as the end of the series — treating it as the end returns an empty page and stalls the list. Paging eventually reaches the previewed eclipse from the other direction, so pages are merged on peak with `mergeEvents`, and a follow-up page skips the visible-eclipse hunt so it is neither repeated nor duplicated.
- Keep side effects out of a `setState` updater; React may replay or discard one, so decide in the effect body and set state unconditionally. A `live`/cancelled ref must be set on the way in as well as cleared on the way out: a development double-invoke runs the cleanup between two mounts, and a flag that is only ever cleared silently discards every async reply from then on. Give each worker request a ticket too, so a slow answer cannot land on top of a newer one.
- Eclipse pages cost 9–39ms in a worker across the globe, and later ones are cheaper because the visible-eclipse walk stops once it has found one. That is far too little to be worth persisting: a cache would need the moment and the place in its key, and would outlive the ephemeris it was computed from. Keeping the loaded pages in component state across open and close is what actually pays, because it preserves how far the reader had paged.
- Dialogs here label their close control with an sr-only span, not `aria-label`, so browser checks must click `[data-slot="dialog-close"]`. A close that silently does nothing leaves the panel open, and the reopen it is meant to test never happens — verify the dialog actually closed before reading anything into the result.
- A UTC offset belongs to an instant, not to a place: read the device zone's offset at the simulated moment with `zoneOffsetHours`, never from `new Date().getTimezoneOffset()`, or a summer sky inherits a winter offset. Named-zone formatting is testable without touching the host's `TZ`, and the sweep over `Intl.supportedValuesOf('timeZone')` holds every offset to the quarter hour the field accepts.
- A dialog that lists results holds its query as a snapshot taken when it opened. The clock keeps running behind it, and recalculating against it rewrites the answer under the reader. Effects that seed such a panel defer their `setState` through `queueMicrotask`, which is what the react-compiler lint rule asks for here.
- Solar glow must fade to zero before the billboard boundary. Measure corona UVs in solar radii and place its plane at the sphere's tangent circle so close and off-centre views follow the limb. Keep prominences in the Sun's rotating frame. Inspect close-ups and foreground occlusion; overview screenshots alone cannot validate these effects.
- Localization lives in `lib/i18n`; see `docs/i18n.md` for adding languages. Keep IDs and astronomy data language-independent, translate complete sentences at presentation time, and add all new text to each catalog. Never recreate the Three.js scene on a locale change; verify that selection, paused time, and camera survive switching.
- The Layout tab keeps the true-size and true-distance controls together. Topic views may temporarily force a presentation distance mode without overwriting the user's saved preference; navigation and refresh must not overwrite it.
- For CPU regressions, record process CPU alongside scene timings and compare the same settings before/after. A fresh preview process can clear high usage even with unchanged code; do not attribute that drop to an application fix. Avoid per-frame DOM writes for hidden/subpixel labels, cancel queued texture preloads on teardown, and release the old WebGL context during hot replacement.

## Review guardrails

- Keep UI labels and metadata strings separate. Do not reuse labels containing decorative separators (`/`, `·`, arrows, or similar) in document titles, Open Graph, Twitter, or JSON-LD names.
- Treat metadata as untrusted output: escape `<`, `>`, and `&` when serializing JSON-LD into a `<script>` element, and test that a value containing `</script>` cannot close the block.
- For App Router/Vinext, use route-group root layouts when routes need different document languages. Each root layout must directly render exactly one `<html>` and `<body>` and import global CSS; shared providers may remain child components. Keep async `params` Promise types for the current Vinext/Next 15+ contract.
- Build-generated, environment-dependent public assets such as sitemaps and robots files must be ignored and generated during builds; never commit host-specific output.
- Normalize external base URLs to an HTTP(S) origin before using them for canonical, Open Graph, or sitemap URLs. Client-imported modules must not assume `process` exists.
- Convert values to the displayed unit before formatting metadata (for example, days to years), and test representative long-period values.
- Validate structured-data hierarchy and links. Breadcrumb ancestors must link to their own collection pages rather than the current entity page.
- Cache locale-independent catalogs and URL snapshots within loops or operations; avoid repeated parsing and lookup.
- Add every new translation ID to every catalog, and verify localized metadata, `lang`, canonical/hreflang, and stable IDs in the static export.
- When moving route modules, update source-inspection tests and run the full test, lint, type-check, and production-export checks.
- Social previews need both a subject-first square image and a 1200×630 card because clients crop and cache `og:image` differently; keep the square first in metadata, embed attribution in generated derivatives, and use a bundled licensed font for localized card text.
- Keep site navigation links visually consistent and distinguish them from external sources: internal profile links have no outbound arrow, while source links retain an arrow and should not repeat a URL already shown in the same panel.
- Named asteroids live in `lib/asteroids.ts` with dated JPL snapshots; Ceres remains a dwarf planet. Asteroids use shared physical display scaling, body-specific mission/PDS shape assets and maps where available, and measured-albedo/spectral materials where no global map is published. Pallas uses the published partial Carry et al. K-band map sampled onto matching DAMIT model 102 faces (unknown pixels are mean-filled); Psyche uses DAMIT 1806 facet albedo; Juno has no downloadable global albedo map. Ceres intentionally uses its near-spherical observed fallback plus Dawn map/normal data. They are registered after the eclipse system because they are not eclipse receivers. Keep both collapsed navigation groups crawlable, auto-expand the selected category, and extend the bundled share-card font for new localized names.
- Planet terrain is generated by `scripts/generate-planet-terrain.ts`: read each source's longitude origin (Mercury/MOLA 0°, Venus/ETOPO2 −180°), not a universal half-turn. Heights are packed RG16; matching normals are object-space, not tangent-space. Rebuild CPU geometry/normals/bounds for picking, keep poles/seams closed, and preserve mean radius when flattening. DEM landmarks and the independent toggle tests protect these conventions. DAMIT models are Z-north and need the proper `(x,y,z) → (x,z,−y)` rotation; facet atlases must only be applied to their paired mesh.
- Lazy loading must not erase visible neighbors when selection changes. Retain visited asteroid models and standard color/normal maps through navigation; downgrade high-resolution maps without detaching the current map. Verify Ceres → Mars keeps Ceres textured and revisiting a loaded asteroid reuses its model. Opt-in planetary terrain still releases when disabled or no longer focused.
- The schematic main belt uses six instanced rock batches in `components/asteroid-belt.ts`, with 20/80-triangle distance LODs. GPU orbit/spin transforms use the simulation's J2000 days, split into whole/fractional days; integer spin turns/day keep day boundaries continuous. Orbital rates depend on orbital radius, not display size. Keep appearance randomness separate from the shared population seed, include every orbit/spin phase and both LODs in culling bounds, and dispose inactive geometries too. Compare overview and Ceres close-ups; overview alone hides square-point or silhouette regressions.
- Outer small-body structures are authored at illustrated radii. With distances to scale, `lib/display-scale.ts` moves each band to the heliocentric distance its own region card quotes, and the Oort cloud stays illustrated-only because it begins near 2,000 AU. Keep the authored radii and their AU targets in that one table so a band cannot drift from the layer it rescales.
- Fresh worktrees need dependencies matching their lockfile; a shared checkout's `node_modules` may lack newer packages. Keep temporary TypeScript backups outside the compiler's include paths (or use a non-TypeScript extension).
- Shared observations are encoded and validated in `lib/share-view.ts`; the explorer applies them once, after the hash has selected a body, then strips the consumed query. A link is recognized by its moment alone: the remaining keys describe framing only, and most are bare single letters that ordinary tracking and redirect parameters collide with; a link carrying no usable moment opens on the current sky rather than at the floor of the simulated range. Keep observer coordinates and display preferences out of the link so it cannot overwrite a recipient's own settings. The landing pages under `[locale]/share` must carry neither `og:url` nor a canonical link: crawlers rewrite a posted link to whichever is present, which would discard the moment the link carries. A static export cannot read that query while rendering, so the card names the body only; the exact time rides in the link and in the attached screenshot. In this Vinext export, a route whose own segment is only `[locale]` still needs its own `generateStaticParams`. `scripts/check-share-export.ts` protects all of this in production output.
- A shared camera pose is a ratio of the body's own framing distance plus its two angles, so it survives different size and distance settings. The scene must reapply it on every reframe rather than consuming it once: an aspect change or a resize retriggers the automatic framing and would otherwise drop the recipient back to the default angle. It is released when the viewer grabs the controls, and cleared when they follow a different body.
- The shared frame carries its own link as a QR badge (`uqr` in `lib/share-image.ts`). Draw it dark on its own card with four clear modules around it and whole-pixel modules, never inverted over the sky: a camera fails on blurred neighbours and low contrast first. A scanner separates modules by luminance, not brightness, so the card is toned far down from white to sit in a dark frame while keeping a wide contrast margin; `qrBadgePalette` and the contrast test hold that trade. Verify a rendered badge by decoding it with the browser's own `BarcodeDetector`, and when it fails, downscale with and without a contrast boost to tell a resolution limit apart from a contrast one.
- A code burnt into the shared frame cannot also serve the dialog: the preview scales the whole image down, which left it near one CSS pixel per module and only readable from a few centimetres. Sizing it up cannot fix that, since surviving that downscale would need a card taking nearly half the frame. `components/share-qr.tsx` draws a second one at device resolution, presented at exactly the pixels it was drawn with so nothing resamples the modules; measure in device pixels per module, not CSS.
- No page may write to a photo library, and a phone's download folder is not where a social application looks for a picture, so on a coarse pointer the save action hands the frame to the system sheet as an image on its own (`saveImageRoute`): a sheet given a link beside the image offers to forward the pair rather than to file the picture, and only an image alone is offered the save action that reaches the album. Keep the preview a real `<img>` — holding a finger on one is the only way into the album in an in-app browser that has no sheet at all — and leave the download in place for a fine pointer, where a file on disk is what was asked for.
- Scene capture renders explicitly before reading the canvas, because `preserveDrawingBuffer` is off; do not split those two steps across an await. This also makes a capture work while the animation loop is halted, which it is whenever `document.hidden` is true — a hidden browser pane renders a black scene even though its DOM screenshots look normal, so never read a blank canvas as a rendering regression.
- PWA assets are generated before both production builds; `scripts/build-pwa.ts` bundles the worker after Vinext finishes. Keep explorer HTML and compiled chunks in the same precache revision, bypass APIs/RSC/third-party traffic, and let new workers wait for old clients to close. Test offline behavior using production output on a separate origin from development, including astronomy workers, localized profile fallback and cache cleanup after updates.

- Deployment build warnings have distinct owners. Vercel's `engines.node` notice fires whenever the range intersects the major above its newest runtime (`25.x` today), so an open `>=22.13.0` warns on every deploy while still selecting 24.x; pin the supported majors instead and keep both READMEs in step. npm records reviewed install scripts in `package.json#allowScripts`, keyed `name@range`, so one `esbuild@0.27.3 || 0.28.2` entry covers both installed copies; rerun `npm approve-scripts <pkg>` after a bump moves any of them. Two client chunks exceed Rolldown's 500 kB default on purpose — Three.js, and the translation catalogues that the synchronous `translator()` loads for every language at once — so `vite.config.ts` budgets `chunkSizeWarningLimit` just above them rather than switching the check off. The `[PLUGIN_TIMINGS]` breakdown is Rolldown reporting on Vinext's own plugins, not a project defect.
